一.字符串逃逸

在反序列化中,成员属性数,成员属性名称长度和成员属性长度都需要与所提供的序列化字符串一致,否则在反序列化时会返回bool(false)

序列化类A之后得到序列化字符串

通过长度判断反序列化其中字符是功能性字符还是字符串

在前面字符串没有问题的时候,;}是反序列化结束符,后面的字符串不影响反序列化结果

O:1:"A":2:{s:2:"v1";s:5:"lu1ux";s:2:"v2";s:4:"lulu";}与O:1:"A":2:{s:2:"v1";s:5:"lu1ux";s:2:"v2";s:4:"lulu";}12345678;}反序列化后的结果是一样的

1.反序列化漏洞CVE-2016-7124

版本要求:

PHP5<5.6.25

PHP7<7.0.10

漏洞产生原因:
如果存在__wakeup方法,调用unserialize()方法,但是序列化字符串中表示对象属性个数的值大于真实的属性个数时,会跳过对__wakeup()的执行

3.fast-destruct

在PHP中如果单独执行unserialize()函数，则反序列化后得到的生命周期仅限于这个函数执行的生命周期，在执行完unserialize()函数时就会执行__destruct()方法

而如果将unserialize()函数执行后得到的字符串赋值给了一个变量，则反序列化的对象的生命周期就会变长，会一直到对象被销毁才执行析构方法

快速析构的原理：

当php接收到畸形序列化字符串时，PHP由于其容错机制，依然可以反序列化成功；

但是由于给的是一个畸形的反序列化字符串，是不标准的，php对这个畸形序列化字符串得到的对象不放心，会赶紧把该对象清除掉，就会触发其析构方法。

这样就会提前触发析构方法，不需要等到所用语句都执行结束，也就可以避免一些安全检查方法的调用。

一种方式就是修改序列化字符串的结构，使得完成部分反序列化的unserialize强制退出，提前触发__destruct，其中的几种方式如下:

1.修改序列化元素个数数字

2.去掉序列化尾部 }

5.使用C绕过

当使用C代替O来标识对象类型时，反序列化将创建一个新的类而不是对象，因为新的类没有被序列化过，所以它没有任何属性或方法，__wakeup魔术方法和__destruct也就不会自动调用。但是，这种方法的缺点是，如果在原先的利用链中需要使用类的属性这个方法就行不通了。

六.phar反序列化漏洞

JAR是开发Java程序一个应用,包括所有的可执行文件,可访问的文件,都打包进了一个JAR文件里,使得部署过程十分简单.

PHAR(“php ARchive”)是php里类似于JAR的一种打包文件.对于PHP5.3或更高版本,Phar后缀文件是默认开启支持的,可以直接使用它

文件包含:phar伪协议,可读取.phar文件

Phar结构

stub phar 文件标识,格式为xxx<?php xxx;__HALT_COMPiLER();?>;(头部信息)

manifest压缩文件的属性等信息,以序列化存储;

contents压缩文件的内容;

Phar协议解析文件时,会自动触发对manifest字段的序列化字符进行反系列化

Phar漏洞原理

manifest压缩文件的属性等信息,以序列化存储;存在一段序列化的字符串

调用phar伪协议,可读取.phar文件;

Phar协议解析文件时,会自动触发对manifest字段的序列化字符串进行反序列化

Phar需要PHP>=5.2且在php.ini中将phar.readonly设为off(注意去掉前面的分号)

Phar使用条件

  1. phar文件能上传到服务器端; (一般只要有上传点就能实现)

  2. 要有可用反序列化魔术方法作为跳板;

  3. 要有文件操作函数,如file_exists(),fopen(),file_get_contents()等

  4. 文件操作函数参数可控,且: / phar等特殊字符没有被过滤

注:

  1. Phar文件上传的文件名后缀没有要求,例如上传test.phar和上传test.png效果是一样的,,上传的如果是test.phar,就是?filename=phar://test.phar

    如果上传的是test.png,就是?filename=phar://test.png

  2. 需要__destruct()或者__wakeup()魔术方法做跳板,不然phar文件只是进行一个反序列化,不会有任何其他操作

  3. 4.即文件操作函数中的函数不是写死的
